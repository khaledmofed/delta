## 3. Insurer integrations

### 3.1 Dubai Insurance (DIN) — "IIRIS" by Assuretech, spec V0.0.3

- **UAT URL:** `https://uatbrokerportal.dubins.ae`. No IP whitelist.
- **Contact:** DIN Senior Application Analyst (name and email in the DIN email thread).
- **Credentials:** UAT username `DELTA_API`. The password is in the email thread; put both in `.env` as `DIN_USERNAME` and `DIN_PASSWORD`.
- **Flow:**
  1. `POST /api/v1/User/Auth` returns a JWT in `data`.
  2. `POST /api/v1/Insurance/GenerateQuote` with header `X-REQUEST-ID`. The body needs the full customer, licence and vehicle data **plus documents as base64**, sent **before** pricing.
  3. `POST /api/v1/Insurance/ChooseScheme` returns the final price and a `paymentUrl`. Payment happens on DIN's own hosted page.
  4. `GET /api/v1/Insurance/GetPaymentInfo` returns `polNo`, `polStatus` and `paymentStatus`. Poll it after payment.
- **Rules:**
  - Dates are `dd/MM/yyyy`.
  - DIN code lists are in `database/data/din-codes.json`, seeded into the `insurer_codes` table.
  - Document codes: 103 / 105 = EID front / back, 101 / 102 = Mulkiya front / back, 106 / 121 = licence front / back, 107 = Bank LPO.
- **Status as of 10-Nov-2026:**
  - ✅ Auth works.
  - ❌ GenerateQuote always returns **8013 "Civil id has been expired"**. This happens even with a real Emirates ID valid until 2028. Request ID for tracing: `0d6ac3cc-4601-4dcf-8d92-becb974cbddb`.
    - We sent DIN the payload and asked them to check.
    - Our test used 1×1 placeholder images for the documents. DIN may read the EID expiry from the image itself.
  - The sample chassis given in the DIN spec returns 8010, because that car already has an active policy (use a real customer vehicle to test).
  - **Still to ask DIN:**
    - Token TTL
    - Payment return URL and webhook (none documented)
    - Test payment card
    - Document code list and which documents are mandatory
    - Cancellation, endorsement and renewal APIs
  - **Data issue in DIN's code lists:** the UAE has 3 nationality codes (102, 325, 394). We use 102. Some banks are duplicated.

### 3.2 Al Wathba (AWNIC) — Insure API, Motor Aggregators

- **UAT base URL:** `https://insurance-uat.awnic.com/InsureApiBYUAT/API`
- **API docs:** https://insurance-uat.awnic.com/InsureApiUAT/docs/repoMotor.html
- **Headers on every call:** `Partner-Id`, `Api-Key`. The Customer-Code is also needed. All three values are in the email from AWNIC’s integration contact dated 6-Nov-2026; put them in `.env` as `AWNIC_*`.
- **IP whitelisting is required.** Nothing works until AWNIC whitelists our server IP. Khaled's PC has a dynamic IP (check the current one before asking AWNIC to whitelist it); the UAT server needs a static IP.
- **Flow** (from the Postman collection, which is not in the repo):
  1. `motor/masterList` and `motor/masterData`: masters such as NATIONALITY, VEHICLE_MAKE_AD, VEHICLE_MODEL_AD, VEHICLE_YEAR_AD and VEHICLE_AD_SPEC_DESC.
  2. `motor/motorADVechicleDescription`: trims with min / avg / max price.
  3. `motor/motorCalcPremiumAmwaj`: returns plans.
  4. `motor/initializePolicyGeneration`: takes `paymentSuccessURL` and `paymentFailURL` and creates the payment.
  5. `motor/finalisePolicyGeneration`: issues the policy after payment.
  6. `motor/motorDownloadDocument` and `motor/motorUploadDocument`: policy documents.
- **Rules:**
  - Dates are `dd-MON-yyyy`, for example `12-OCT-1985`.
  - Vehicle-first flow. No documents are needed before pricing.
  - AWNIC has its **own codes**. The DIN → AWNIC mapping goes in `insurer_codes.meta.din`.
- **Status:** code written but not yet tested. Waiting for IP whitelisting.

## 4. What exists in this Laravel project

- **Laravel 12 skeleton.** `vendor/` is not committed; run `composer install`. Config files fall back to framework defaults except `config/insurers.php`.
- **Migrations:**
  - users, sessions, cache, jobs
  - products, insurers, insurer_product, insurer_codes
  - customers (EID and licence numbers encrypted), vehicles, leads
  - quote_requests (`input` encrypted), quotes, orders (state machine), payments, policies, documents (private disk)
  - api_logs, audit_logs
- **`app/Insurers/` layers:**
  - `Contracts/InsurerAdapter`: `ping()`, `quote()`, `checkout()`, `policyStatus()`.
  - `Data/*` DTOs: `MotorQuoteInput` holds dates in ISO format and codes from the DIN lists.
  - `Din/DinMapper` and `Awnic/AwnicMapper`: pure PHP with no Laravel dependency, unit-tested.
  - `Din/DinAdapter` and `Awnic/AwnicAdapter`: HTTP calls through `Support/InsurerHttp`, which writes a row to `api_logs` with secrets and base64 redacted by `Support/Redactor`.
- **`app/Services/QuoteEngine`:** asks every enabled insurer and stores normalised quotes. One insurer failing never blocks the others.
- **Artisan commands:**
  - `insurers:ping {din|awnic}`
  - `insurers:quote-test {insurer} database/data/motor-quote.example.json`
  - `awnic:sync-masters --dump`
- **Tests:** `tests/Unit/DinMapperTest`, `AwnicMapperTest` and `tests/Feature/DinAdapterTest` (uses Http::fake).
  - The mapper unit tests were run outside Laravel and passed.
  - The full suite has **not yet been run with real Laravel**. Run `composer install && php artisan test` first and fix anything that fails.
- **`deploy/`:** `server-setup.sh` (Ubuntu 24.04: nginx, PHP 8.3, MySQL, Redis, Supervisor, certbot; prints the public IP), `deploy.sh`, `nginx.conf` and `supervisor-worker.conf`.

## 7. Conventions

- Never put insurer credentials in code or Git. Use `.env` only.
- Never log passwords, API keys, tokens or document content (see `Redactor`).
- Customer documents stay on the private disk and are never placed in `public/`.
- Every insurer call goes through an Adapter. Controllers never call insurer APIs directly.
